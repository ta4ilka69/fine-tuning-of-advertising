
# Тесты фронтенда

Нужны Node.js 24 и npm. Команды выполняются из `frontend/` после `npm ci`.

```sh
npm run check
npm run check:api
npm run test:coverage
npm run build
npm run check:bundle
npx playwright install chromium
npm run test:e2e

```

Покрытие доступно в `frontend/coverage/index.html`. Минимум: 80% строк, инструкций и функций, 75% ветвей условий. Проверки браузера запускают собранное приложение автоматически.

## Общие компоненты

Компонентные тесты проверяют действия с клавиатуры, доступные названия, подписи и ошибки полей, блокировку кнопок, уведомления и меню пользователя. Страница состояний находится в `tests/ui/`, собирается перед тестами Playwright и открывается через тестовый перехват запросов. В production-сборку приложения она не входит.

Для просмотра состояний локально:

```sh
npx vite --config tests/ui/vite.config.ts --port 4174

```

Откройте `http://localhost:4174/`. Варианты шапки: `?header=user` и `?header=admin`. Кнопки меняют только счётчик действий на тестовой странице.

## Вход и регистрация

Формы проверяются вместе с приложением и существующей cookie-сессией. Браузерные сценарии используют локальный тестовый HTTP-сервер: успешные ответы, ошибки полей, занятый логин, ограничения частоты, обрыв сети, некорректный ответ и задержки запросов. Проверяются границы Credentials, Unicode и пробелы в пароле, клавиатура, переходы между формами, история браузера, перезагрузка, выход и защита страниц.

## Объявления

Список проверяется стабильным тестовым HTTP-сервером по контракту OpenAPI: неполные черновики, типы недвижимости и сделок, точные суммы, статусы последнего запуска и сохранённого результата. Проверяются непрозрачные курсоры, повторные нажатия, дубли, конец списка и ручной повтор после ошибки догрузки с сохранением записей.

Сценарии включают 401 с перепроверкой сессии, ошибки сети и сервера, некорректные ответы, выход, смену пользователя и запоздалые ответы. Просмотр объявления и экран создания проверяются с прямым открытием, перезагрузкой и историей браузера. Тестовые данные доступны только тестовому серверу.

## Браузеры

Для Chromium, Firefox и WebKit:

```sh
npx playwright install --with-deps
npm run test:browsers

```

## Скриншоты

Проверяются главная на ширинах 1440, 768, 360 и 320 px, состояния компонентов на 1440 и 320 px, наведение, фокус и нажатие кнопки. Для списка объявлений сравниваются desktop/mobile, пустой список на двух ширинах, загрузка и ошибка. Для входа сравниваются desktop, mobile, ошибка и загрузка; для регистрации — desktop, mobile, 320 px, ошибки полей, занятый логин и загрузка. Доступность списка и обеих форм проверяется на ширинах 320, 390, 768 и 1440 px.

Скриншотные эталоны хранятся в `frontend/tests/e2e/screenshots/`. Они сравниваются в Linux ARM64 в образе `mcr.microsoft.com/playwright:v1.64.1-noble`. Команда сравнения в этом окружении:

```sh
npm run test:visual

```

Для обновления эталонов запустите `Update screenshots` во вкладке Actions, выбрав ветку PR. Артефакт `screenshots-<SHA>` содержит каталог `chromium/`: его нужно поместить в `frontend/tests/e2e/screenshots/` и добавить изменения в PR. Обычный CI эталоны не обновляет.

## CI

В Actions сохраняются отчёты покрытия, браузерные отчёты и различия скриншотов на 14 дней. `Browser compatibility` проверяет три браузера ежедневно и запускается вручную. Проверка `Frontend required` объединяет обязательные проверки PR.

В PR тесты фронтенда запускаются при изменениях `frontend/` или его CI. Изменения только в `backend/` запускают проверку общего Compose без отдельных тестов фронтенда. Compose также проверяется при изменениях фронта и общей конфигурации запуска. Изменения только корневого README не запускают эти проверки. Ручной запуск `Verify` выполняет все проверки.
